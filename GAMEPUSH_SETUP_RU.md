# Настройка PULSEFADE в GamePush

## 1. Создание проекта

1. Создать игру в панели GamePush.
2. Скопировать `Project ID` и `Public Token`.
3. Создать `.env.local` на основе `.env.gamepush.example`.
4. Не добавлять секретные серверные ключи в клиентский проект. Для браузерного SDK используется только публичный ключ.

```dotenv
VITE_GAMEPUSH_ENABLED=true
VITE_GAMEPUSH_PROJECT_ID=12345
VITE_GAMEPUSH_PUBLIC_TOKEN=public_key_from_panel
VITE_GAMEPUSH_PRELOADER=false
VITE_GAMEPUSH_STICKY=false
```

При пустых переменных игра запускается локально через `NullGamePlatform`.

## 2. Поля игрока

В панели GamePush открыть раздел **Players / Игроки → Fields / Поля** и создать числовые поля.
Все значения по умолчанию — `0`.

| Ключ | Название RU | Название EN | Тип | Public | Important | Назначение |
|---|---|---|---|---:|---:|---|
| `pulses` | Импульсы | Pulses | Number | нет | да | Мягкая валюта и награда за раунды |
| `rounds_played` | Сыграно раундов | Rounds played | Number | нет | нет | Прогресс и сегментация |
| `perfect_hits` | Идеальные попадания | Perfect hits | Number | нет | нет | Суммарная статистика |
| `misses_total` | Промахи | Misses | Number | нет | нет | Суммарная статистика |
| `best_combo` | Лучшая серия | Best combo | Number | да | нет | Общий рекорд серии |
| `best_adaptive` | Рекорд Adaptive | Adaptive best | Number | да | нет | Рекорд режима |
| `best_chaos` | Рекорд Chaos | Chaos best | Number | да | нет | Рекорд режима |
| `best_marathon` | Рекорд Marathon | Marathon best | Number | да | нет | Рекорд режима |
| `best_zen` | Рекорд Zen | Zen best | Number | да | нет | Рекорд режима |
| `best_duel` | Рекорд Duel | Duel best | Number | да | нет | Лучший локальный результат дуэли |

Базовое поле `score` создавать не нужно. Интеграция записывает в него лучший результат режима Adaptive;
оно используется основной таблицей лидеров.

Рекомендуемые ограничения полей:

- `pulses`: от `0` до `1 000 000 000`;
- счётчики: от `0` до `2 147 483 647`;
- рекорды: от `0` до `2 147 483 647`.

После добавления полей открыть тестовую страницу GamePush, сыграть раунд и убедиться, что значения меняются.
Если поле не создано, адаптер выводит предупреждение в консоль и не блокирует игру.

## 3. Сохранения

Интеграция ожидает `gp.player.ready`, меняет локальное состояние игрока и вызывает:

```ts
gp.player.sync({ storage: 'preferred' });
```

Синхронизация выполняется после завершения раунда и после выдачи rewarded-награды.
В настройках каждой площадки выбрать подходящее preferred-хранилище. Для рекордов и публичных полей
включить сохранение публичных полей в облако, если конкретная площадка этого требует.

## 4. Таблица лидеров

Основной лидерборд сортируется по `score` по убыванию. В игре открывается стандартный GamePush overlay:

```ts
gp.leaderboard.open({
  orderBy: ['score'],
  order: 'DESC',
  limit: 20,
  withMe: 'first',
  showNearest: 3,
});
```

Для Яндекс Игр в консоли площадки создать таблицу с техническим именем `score`, если это требуется выбранной конфигурацией публикации.

После первого релиза можно добавить отдельные таблицы по `best_chaos`, `best_marathon` и `best_combo`.
В MVP лучше оставить один понятный мировой рекорд, чтобы не дробить небольшую аудиторию.

## 5. Реклама

### Rewarded video

Показывается только после явного нажатия кнопки **«×2 PULSES · РЕКЛАМА»** на экране результата.
Базовая награда уже сохранена до показа. После успешного просмотра начисляется ещё столько же:

```text
baseReward = clamp(floor(score / 100), 1, 250)
итог после rewarded = baseReward × 2
```

Кнопка появляется не раньше второго завершённого раунда. При отсутствии рекламы игрок видит сообщение,
базовая награда не теряется.

### Fullscreen

Показывается только на экране результата, никогда во время активного ритм-раунда.
Локальные ограничения поверх ограничений площадки:

- не раньше 4-го завершённого раунда;
- не чаще одного показа на 3 завершённых раунда;
- не чаще одного показа в 180 секунд;
- rewarded и fullscreen не предлагаются на одном экране результата;
- быстрый переход игрока в следующий раунд отменяет запланированный fullscreen.

### Preloader

По умолчанию выключен. Главная особенность PULSEFADE — старт первого импульса без меню и задержки.
Включать preloader стоит только после A/B-теста и только если реальная загрузка ассетов станет заметной.

### Sticky

По умолчанию выключен: нижняя лента темпа является частью игрового поля, а баннер может закрыть её.
Для sticky потребуется отдельная безопасная зона и перерасчёт viewport, а не простое включение флага.

## 6. Аналитические цели

Интеграция отправляет:

| Цель | Значение | Когда |
|---|---|---|
| `GAME_READY` | — | SDK и игрок готовы |
| `ROUND_START` | mode id | Начат раунд |
| `ROUND_FINISH` | mode id | Раунд завершён |
| `ROUND_SCORE` | score | Результат раунда |
| `ROUND_ABORT` | mode id | Игрок ушёл в меню |
| `REPLAY_START` | mode id | Запущен повтор |
| `REPLAY_FINISH` | mode id | Повтор завершён |
| `REWARDED_REQUEST` | — | Нажата rewarded-кнопка |
| `REWARDED_SUCCESS` | — | Реклама успешно просмотрена |
| `REWARDED_CANCEL` | — | Реклама закрыта/недоступна |
| `REWARDED_GRANTED` | amount | Награда начислена |
| `FULLSCREEN_REQUEST` | — | Запрошен fullscreen |
| `FULLSCREEN_SHOWN` | — | Fullscreen показан |
| `FULLSCREEN_UNAVAILABLE` | — | Показ не состоялся |
| `LEADERBOARD_OPEN` | — | Открыт лидерборд |

В панели проекта подключить поддерживаемую площадкой систему аналитики. Не включать сторонние трекеры
на площадках, где их правила запрещают.

## 7. Пауза и звук

Реализованы три независимые причины паузы:

- событие паузы GamePush/площадки;
- показ рекламы;
- скрытие вкладки браузера.

Во время паузы игровое время не продвигается, ввод очищается, звук и вибрация выключены.
После возврата во вкладку показывается кнопка **«Продолжить»**. Это важно для ритм-игры:
следующий импульс не должен стать автоматическим промахом из-за системного диалога или рекламы.

## 8. Сборка и загрузка

В полном проекте выполнить:

```bash
npm install
npm run test
npm run typecheck
npm run build
```

Загружать нужно содержимое `dist/`, при этом `index.html` должен находиться в корне архива публикации.
Проверить, что Vite использует относительные пути к ассетам, если выбранная площадка размещает игру не в корне домена.
Обычно для этого в `vite.config.ts` задают:

```ts
export default defineConfig({
  base: './',
});
```

## 9. Матрица приёмки

Проверить минимум:

| Сценарий | Ожидаемый результат |
|---|---|
| SDK отключён | Игра стартует без облака и рекламы |
| SDK CDN недоступен | Через таймаут запускается no-op режим |
| Первый запуск | Сразу начинается Adaptive, рекламы нет |
| Второй результат | Может появиться добровольное ×2 rewarded |
| Rewarded просмотрен | Начислена дополнительная награда, баланс обновлён |
| Rewarded недоступен | Показано сообщение, базовая награда сохранена |
| Четыре раунда, прошло 3 минуты | Fullscreen возможен только между раундами |
| Реклама открыта | Игра, ввод, звук и вибрация остановлены |
| Вкладка скрыта | Таймер и импульсы остановлены |
| Возврат во вкладку | Показана кнопка «Продолжить» |
| Перезагрузка | Рекорд и pulses восстановлены |
| Лидерборд | Видны топ, игрок и ближайшие позиции |
| Телефон/desktop | Overlay и кнопки не перекрывают поле |

## 10. Перед отправкой на модерацию

- проверить Chrome, Safari, Firefox, Opera и Яндекс Браузер;
- проверить обычный и приватный режим;
- проверить мобильные размеры от 360×740 и desktop 1920×1080;
- убедиться, что нет прокрутки страницы, выделения по long tap и системного контекстного меню;
- проверить RU и EN локализации, переполнение кнопок и переносы;
- проверить загрузку на медленной сети;
- проверить AdBlock и отсутствие рекламного fill;
- проверить возврат после каждого внешнего GamePush overlay;
- провести минимум 20 полных сессий по 5–10 минут без ошибок в консоли.
