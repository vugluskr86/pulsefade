## 2. Игровой контент: Adaptive Journey — 12 испытаний

Центральный контент MVP. 12 коротких испытаний (30–45 секунд каждое), прохождение
которых даёт игроку понятную цель и видимый прогресс.

- [x] **2.1. 4 вводных испытания (1–4)**
  - **Испытание 1:** стабильный ритм, широкое окно PERFECT, без событий.
  - **Испытание 2:** плавное ускорение темпа.
  - **Испытание 3:** пауза/замедление.
  - **Испытание 4:** двойной паттерн (double-beat).
  - Каждое — отдельная конфигурационная запись (режим, seed, длительность, набор
    разрешённых паттернов, eventChance).

- [x] **2.2. 4 испытания на серии и множитель (5–8)**
  - Фокус на удержании combo: более узкие окна, выше награда за длинные серии.
  - Испытание 5: накопление ×2 множителя.
  - Испытание 6: удержание серии при смене темпа.
  - Испытание 7: комбинированные ускорения.
  - Испытание 8: серия с паузами без сброса combo.

- [x] **2.3. 4 испытания на смешанные паттерны (9–12)**
  - Испытание 9: double + ускорение.
  - Испытание 10: удержание (hold) + смена темпа.
  - Испытание 11: два центра (choice) + замедление.
  - Испытание 12: все типы событий вместе, финальное испытание.

- [x] **2.4. Конфигурация испытаний как данные, не хардкод**
  - Каждое испытание — объект в `config/journey.ts` (или подобном):
    ```ts
    {
      id: 1,
      nameKey: 'journey.1.name',
      seed: number,
      durationSec: 35,
      allowedPatterns: PatternId[],
      eventChance: 0..1,
      thresholds: { bronze: number, silver: number, gold: number }
    }
    ```
  - Не дублировать логику, а переиспользовать существующий `RoundRunner` с разными
    параметрами.

- [x] **2.5. Оценка испытаний: Bronze / Silver / Gold**
  - Gold: score ≥ порога + perfect ratio ≥ порога.
  - Silver: score ≥ порога или perfect ratio ≥ порога.
  - Bronze: завершение испытания без досрочного выхода.
  - Пороги настраиваются индивидуально для каждого испытания.

- [x] **2.6. Экран выбора испытания и прогресс**
  - Список из 12 ячеек, каждая показывает: номер, название, лучшую медаль.
  - Открываются последовательно: нельзя играть испытание 5, не завершив 4.
  - Визуальный индикатор общего прогресса (X/12, процент).

- [x] **2.7. Сохранение прогресса Journey**
  - Лучшая медаль, лучший score и perfect ratio по каждому испытанию.
  - Сохраняются в player fields или в `gp.player` storage.
  - После перезагрузки прогресс восстанавливается.

## 3. Свободные режимы

Пять режимов, доступных вне Journey. Каждый должен быть проверен и работать
без ошибок.

- [x] **3.1. Adaptive — режим по умолчанию**
  - 30 секунд, eventChance = 0 (только базовый one-tap).
  - Меняющийся темп согласно паттернам из `domain/patterns/library.ts`.
  - Именно этот режим запускается при первом входе в игру.

- [x] **3.2. Chaos — высокая интенсивность**
  - Короткие интервалы, высокая плотность событий (double, hold, choice).
  - Все 6 базовых + 3 chaos-паттерна.
  - 30 секунд.

- [x] **3.3. Marathon — на выносливость**
  - Постепенное ускорение темпа с течением времени.
  - Раунд длится до 3 MISS (или настраиваемого лимита).
  - Возможность одного revive через rewarded (после soft launch).

- [x] **3.4. Zen — без оценки**
  - Нет MISS, нет штрафов, нет таймера.
  - Бесконечный поток импульсов в стабильном приятном ритме.
  - Подходит для знакомства с механикой.

- [x] **3.5. Локальный Duel — общий seed, два игрока**
  - Запуск через `GameShell.startDuel()`.
  - Общий seed → одинаковая последовательность ударов.
  - `RunRecorder.buildReplay()` для повтора лучшей серии.
  - Сравнение score двух прохождений на одном устройстве.

- [x] **3.6. Экран выбора режимов**
  - Понятные иконки/названия, краткое описание каждого режима.
  - RU/EN локализация названий и описаний.
  - Доступен после первого раунда или из главного меню.

## 4. Ежедневный seed

- [x] **4.1. Детерминированная последовательность на день**
  - Seed = `hash(date + global_secret)`, одинаковый для всех игроков в течение
    календарного дня (UTC).
  - Используется существующий `SeededRng` из `core/`.

- [x] **4.2. Отдельный режим «Daily»**
  - Запускается из меню режимов.
  - Длительность 30–45 секунд.
  - Показывает результат после завершения.

- [x] **4.3. Награда за первую попытку**
  - 50–150 pulses за первое завершение daily-раунда в текущий день.
  - Небольшой бонус (25–50 pulses) за улучшение личного рекорда дня.
  - Награда начисляется только один раз в день (первая попытка) + бонус при
    улучшении.

- [x] **4.4. Заглушка для будущей daily-таблицы**
  - В MVP лидерборд daily не делается (план — этап B).
  - Но архитектура должна позволять добавить отдельную таблицу `daily_score`
    без переписывания.

## 9. Реклама: Rewarded ×2

- [x] **9.1. Кнопка на экране результата**
  - Текст: «×2 PULSES · РЕКЛАМА» (RU) / «×2 PULSES · AD» (EN).
  - Появляется не раньше второго завершённого раунда.
  - Кнопка заметная, но не главный объект экрана — основная кнопка «Ещё раз»
    всегда крупнее.

- [x] **9.2. Логика до и после показа**
  - Базовая награда (`clamp(floor(score / 100), 1, 250)`) начисляется и
    сохраняется ДО показа рекламы.
  - После успешного просмотра: дополнительная награда = базовая награда.
  - Итог: `baseReward × 2`.
  - Если реклама недоступна или отменена — игрок сохраняет базовую награду,
    показывается сообщение.

- [x] **9.3. Текстовые состояния rewarded**
  - RU/EN строки для каждого состояния:
    - реклама доступна (кнопка активна),
    - реклама загружается (спиннер/ожидание),
    - видео не найдено (no fill),
    - просмотр отменён (игрок закрыл),
    - награда начислена (подтверждение с суммой),
    - синхронизация временно недоступна (офлайн).
  - При отсутствии рекламы кнопка заменяется на информационное сообщение,
    базовая награда не теряется.

## 10. Реклама: Fullscreen

- [x] **10.1. Только между раундами**
  - Fullscreen показывается на экране результата, никогда во время активного
    ритм-раунда.
  - После закрытия fullscreen игрок возвращается на экран результата.

- [x] **10.2. Лимиты показа**
  - Не раньше 4-го завершённого раунда.
  - Не чаще одного раза в 3 завершённых раунда.
  - Не чаще одного раза в 180 секунд.
  - Счётчики сбрасываются при перезапуске игры (сессионные, не постоянные).

- [x] **10.3. Не на одном экране с rewarded**
  - Если на текущем экране результата доступен rewarded (кнопка «×2 PULSES»),
    fullscreen НЕ показывается.
  - Приоритет: rewarded > fullscreen.

- [x] **10.4. Отмена при быстром переходе**
  - Если игрок нажал «Ещё раз» до того, как fullscreen был показан, —
    запланированный показ fullscreen отменяется.
  - Таймер между раундами должен давать окно для fullscreen, но не задерживать
    игрока.

- [x] **10.5. A/B-тест частоты (после soft launch)**
  - Подготовить конфигурацию для двух групп:
    | Группа | Интервал | Мин. раундов |
    |--------|----------|-------------|
    | A | 180 сек | 3 |
    | B | 240 сек | 4 |
  - Тест запускается после первой недели soft launch.
  - Критерий выбора: выручка на пользователя + средняя сессия + число повторов,
    а не только eCPM.

- [x] **10.6. Не показывать в первых двух сессиях**
  - Для новых игроков fullscreen отключён в первые две сессии (возврат в игру
    после закрытия браузера считается новой сессией).
  - Счётчик сессий хранится в `gp.player`.

## 17. Пауза, звук, AdBlock и сценарии сбоев

- [ ] **17.1. Три независимые причины паузы**
  - Пауза GamePush/площадки (событие `gp.game.pause`).
  - Показ рекламы (rewarded/fullscreen).
  - Скрытие вкладки браузера (visibility API).
  - Все три работают независимо: если реклама внутри паузы — пауза не
    снимается до возвращения во вкладку.

- [ ] **17.2. Поведение при паузе**
  - Игровое время (Clock) остановлено.
  - Ввод (InputRouter) очищен — следующий импульс не становится
    автоматическим MISS.
  - Звук и вибрация выключены.
  - При возврате во вкладку — кнопка **«Продолжить»** (обязательно,
    критично для ритм-игры).

- [ ] **17.3. AdBlock / нет рекламного fill**
  - Если реклама недоступна:
    - Rewarded: кнопка заменяется на сообщение, базовая награда не теряется.
    - Fullscreen: пропускается, кнопка «Ещё раз» работает без задержки.
  - Игра не должна блокироваться, показывать ошибки или крашиться.

- [ ] **17.4. Нет сети / SDK не загрузился**
  - `NullGamePlatform` запускается при отсутствии SDK.
  - Через таймаут (GamePushLoader.ts) — переход в no-op режим.
  - Игра полностью играбельна без сети, но без рекламы, лидерборда
    и облачных сохранений.

## 20. Soft launch и метрики

- [ ] **20.1. Подготовка к soft launch**
  - Ограниченное число площадок (1–3).
  - Сборка с включённой аналитикой.
  - Все события отправляются в GamePush analytics.
  - Реальные рекламные ID (если доступны для площадок).

- [ ] **20.2. Первые 3 дня — без изменения рекламной частоты**
  - Сбор базовых метрик без A/B-тестов.
  - Ежедневная проверка ошибок и сохранений.

- [ ] **20.3. Сбор воронки первых двух раундов**
  - Воронка: `GAME_READY → ROUND_START → FIRST_INPUT → FIRST_PERFECT →
ROUND_FINISH → RESULT_VIEW → AGAIN_CLICK → второй ROUND_FINISH →
REWARDED_REQUEST/skip → SESSION_5_MIN`.

- [ ] **20.4. Главные метрики для анализа**
      | Метрика | Что диагностирует |
      |---------|------------------|
      | Доля игроков, завершивших 1-й раунд | Понятность первых 30 секунд |
      | Доля нажавших «Ещё раз» | Сила core loop |
      | Раундов за сессию | Удержание внутри визита |
      | Средняя/медианная сессия | Достаточность контента |
      | PERFECT ratio новичков | Справедливость таймингов |
      | MISS после изменения темпа | Читаемость телеграфа |
      | Rewarded opt-in | Ценность pulses и оффера |
      | Rewarded completion | Корректность и доверие |
      | Fullscreen exit rate | Агрессивность рекламы |
      | D1 / D7 | Долгосрочная ценность контента |

- [ ] **20.5. A/B-тесты на этапе soft launch**
  - Один тест сложности: ширина окна PERFECT / минимальное approach time.
  - Один тест fullscreen-частоты: группы A (180/3) и B (240/4).
  - Тесты запускать после сбора базовых метрик (3+ дня).

- [ ] **20.6. Решения по данным**
  - **Core loop слабый** (мало повторов, сессия <3 мин, rewarded не жмут):
    - Не увеличивать рекламу; сократить паузу результата; показать
      «до рекорда осталось N»; усилить feedback PERFECT; упростить
      первые 10 ударов; дать первую косметику после 3 раундов.
  - **Игра слишком сложная** (perfect ratio <15%, выходы после MISS):
    - Увеличить мин. время подлёта; расширить GREAT; отложить fake slowdown
      и double-beat; добавить 2–3 демо-паттерна без наказания.
  - **Rewarded слабый** (opt-in низкий при нормальной сессии):
    - Добавить полезные траты; показывать баланс и ближайшую покупку;
      заменить `×2` на конкретную выгоду.
  - **Fullscreen ухудшает удержание** (выходы после показа, падение повторов):
    - Увеличить интервал до 4–5 мин; не показывать после неудачного раунда;
      показывать только после 2+ последовательных раундов; убрать для
      первых двух сессий.

- [ ] **20.7. Критерии масштабирования**
  - Первый раунд стабильно завершается большинством игроков.
  - «Ещё раз» нажимается достаточно часто для 5+ минутной сессии.
  - Rewarded не вызывает жалоб на потерю награды.
  - Fullscreen не создаёт заметный всплеск выходов.
  - Сохранения и лидерборд работают после перезагрузки и на мобильных
    браузерах.
  - Контент не заканчивается до 10 минут.
